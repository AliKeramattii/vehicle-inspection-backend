## مستندسازی اجباری فرایند پیاده‌سازی

پس از **هر کار پیاده‌سازی یا checkpoint توسعه**، راهنمای عملی فارسیِ فرایند انجام کار را ایجاد یا به‌روز کنید؛ تحویل فقط با شرح نتیجه کامل نیست. راهنما باید به مهندس یا عامل بعدی امکان فهم، بازآزمایی و نگهداری همان نسخه را بدهد. موضوع‌های مرتبط زیر پوشش داده شوند؛ موارد نامرتبط حذف شوند و متن تکراری یا بخش خالی ساخته نشود:

۱. مسئلهٔ حل‌شده و علت آن.
۲. پیش‌نیازها، مجوز مرحله و وضعیت اولیهٔ مخزن/محیط.
۳. فایل‌ها و اجزای بررسی‌شده.
۴. تصمیم‌های معماری و طراحی و دلیل انتخاب آن‌ها.
۵. گام‌های واقعی پیاده‌سازی به‌ترتیب انجام.
۶. فایل‌های ساخته/تغییرکرده و مسئولیت هرکدام.
۷. قطعه‌کدهای کوتاه و مهمِ همان نسخه با توضیح و ارجاع به منبع.
۸. فرمان‌های دقیق توسعه، build، اجرا و آزمون با cwd/محیط لازم.
۹. SQL script، جدول، index و constraint ایجاد/اصلاح‌شده.
۱۰. روش اتصال پایگاه، اجرای migration مصوب و بازیابی شکست، اگر واقعاً اجرا شده‌اند.
۱۱. endpoint، قرارداد request/response و تغییر تنظیمات.
۱۲. روش اجرای محلی قابلیت پیاده‌شده.
۱۳. روش بازبینی دستی و نتیجهٔ واقعی آن، در صورت کاربرد.
۱۴. آزمون‌های خودکار و نتیجهٔ واقعی، با تفکیک اجرای تازه از شاهد تاریخی.
۱۵. خطاهای واقعی و نحوهٔ رفع آن‌ها؛ نبود log با حدس پر نشود.
۱۶. ملاحظات امنیت، محرمانگی و سطح مجوز.
۱۷. commitهای واقعی و وضعیت تأییدشدهٔ push/remote.
۱۸. محدودیت‌ها و تصمیم‌های باز.
۱۹. کار لازم برای توسعه‌دهنده/عامل بعدی و مجوزهای وابسته.
۲۰. درصد کل پیشرفت Backend با مبنای وزنی PLAN.

مرجع ورود، [docs/implementation/README.md](../implementation/README.md) است. گزارش کافیِ موجود را گسترش دهید یا به آن لینک بدهید؛ برای checkpoint آینده فایل صوری، خالی یا گزارش پیاده‌سازیِ رفتار طراحی‌شده نسازید. فلو هر قابلیت باید اجزای واقعی را به هم وصل کند: ورودی و API، service/adapter، منشأ trusted، جدول/transaction، خروجی، خطا/انقضا و روش آزمون؛ فقط اجزای واقعاً پیاده‌شده تشریح شوند. برای SQL، اتصال/metadata، اجرای مصوب schema، مجوز، repository/transaction و recovery فقط تا حد اجرای اثبات‌شده گزارش شوند.

فرمان اجراشده، دستور پیشنهادی بازتولید، پیش‌نویس و نتیجهٔ آزمون برچسب جدا داشته باشند. لاگ، زمان اجرا، ترتیب تاریخی یا رفع خطای ثبت‌نشده جعل نشود؛ کمبود شاهد صریح بماند. قطعه‌کد اختصاصی کارگزاری، credential، PII و خروجی حساس در walkthrough نیاید. شناسه، مسیر، SQL، JSON و فرمان انگلیسی بمانند و توضیح فارسی با code fence قابل کپی باشد. [راهنمای SQL در VS Code](VSCODE_SQLSERVER_SETUP_FA.md) آموزش ابزار است و مجوز اجرای SQL یا DDL ایجاد نمی‌کند.

این قاعده جزو تعریف انجام تمام checkpointهای آینده است: قابلیت در دامنهٔ مصوب، آزمون مرتبط موفق، ثبت بازبینی دستی در صورت کاربرد، walkthrough به‌روز، ریسک‌ها، PLAN/درصد و ثبت/همگام‌سازی امن Git در صورت دسترسی. برای تغییر صرفاً مستنداتی، وجود/پیوند/سازگاری/نبود راز کنترل شود؛ تعهد ساختگی به build/runtime ایجاد نشود.
