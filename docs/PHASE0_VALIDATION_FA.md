# گزارش اعتبارسنجی Phase 0

تاریخ `2026-11-01`؛ این گزارش فقط کنترل مستندات و آماده‌سازی است. کنترل‌های زیر واقعاً اجرا و موفق شده‌اند. هیچ compilation، runtime، SQL migration، پیامک، آزمون IIS یا deployment در Phase 0 انجام نشده است.

این گزارش، ثبت تاریخی همان مرحله است؛ شمار مرجع‌ها و نبود remote به زمان Phase 0 تعلق دارند. [تغییر بعدی تاریخچه برای منع انتشار ZIP](GITHUB_SYNC_FA.md) و [PLAN فعلی](../PLAN.md) وضعیت امروز را نشان می‌دهند. مسیر مطالعهٔ مراحل در [فهرست فرایند پیاده‌سازی](implementation/README.md) است.

## روش انجام و بازبینی

۱. منابع تحویل‌شده، نیازهای مصرف‌کننده و دستورهای مالک خوانده و تعارض‌ها در [شناسنامهٔ منابع](SOURCE_REFERENCES_FA.md) تفکیک شدند؛ mapping ناشناخته با نام حدسی پر نشد.
۲. معماری، قواعد کسب‌وکار، طرح تدریجی SQL، API و آزمون‌های آینده در اسناد فارسی ثبت شدند؛ source برنامه یا DDL تازه ساخته نشد.
۳. وجود فایل‌های الزامی، UTF-8، fence و مقصد لینک‌های تازه، قواعد رسانه/fixture، ignore و الگوهای راز کنترل شدند. hash منابع و دو برداشت وضعیت/اثر انگشت Frontend برای احراز عدم تغییر مقایسه شدند.
۴. محدودیت‌های منابع و پیوندهای قدیمی، نتیجهٔ کنترل و نقطهٔ توقف ثبت و فقط بستهٔ مستندات در Git مستقل Backend نگهداری شد.

ترتیب بالا مسیر ثبت‌شدهٔ تحلیل تا اعتبارسنجی را توضیح می‌دهد؛ متن کامل فرمان‌های ابزار موقت Phase 0 در artifact پایدار نگهداری نشده و فرمان یا زمان اجرای تازه‌ای به آن نسبت داده نمی‌شود. برای بازبینیِ صرفاً مستنداتی امروز، فایل‌ها و پیوندهای تازه/قواعد/hash مربوط به دامنهٔ مجاز بررسی شوند؛ fingerprint تاریخی Frontend نتیجهٔ همان اجراست و مجوز خواندن/اجرای مجدد Frontend ایجاد نمی‌کند.

## محدودهٔ کنترل

۲۱ فایل تازهٔ برنامه‌ریزی شامل سه Markdown ریشه، `.gitignore`، `.gitattributes`، پانزده سند اصلی docs و همین گزارش بررسی می‌شوند. ۴۵ فایل مرجع از قبل وجود داشته‌اند؛ محتوایشان تغییر نمی‌کند. `.gitattributes` بایت مرجع‌ها را هنگام ثبت/بازیابی Git حفظ و پایان خط اسناد تازه را LF می‌کند. ابزار موقت بررسی داخل `.phase0-tmp/`، ignored است و جزء کد برنامه یا artifact تحویل نیست.

## نتیجه

| کنترل | نتیجهٔ واقعی |
|---|---|
| فایل‌های الزامی | هر ۱۹ فایل درخواستی موجود؛ به‌اضافهٔ همین گزارش و `.gitattributes` برای حفظ hash مرجع‌ها؛ جمعاً ۲۱ فایل تازه |
| زبان و ساختار | UTF-8 فارسی، بدون replacement character و بدون code fence باز در اسناد تازه |
| پیوند اسناد تازه | همهٔ مقصدهای نسبی موجودند؛ هیچ پیوند محلی شکسته در اسناد تازه یافت نشد |
| طرح پایگاه | هر ۳۷ جدول مرجع تعیین تکلیف شده؛ ۱۷ جدول تدریجی مشتری با پیشوند BAZDID پیشنهاد شده‌اند |
| قواعد مدرک | هر ده fixed ID، `spec-plate` و چهار alternative، video-360 و سازگاری تاریخی ثبت شده‌اند |
| فایل و SQL | فایل برنامه، solution، project، global.json یا SQL جدید ایجاد نشده؛ SQL مرجع از قبل موجود و اجرا‌نشده است |
| fixture و Session | gate Development/Test، منع SMS mock، fail-closed Production، expiry/replay/rate، SQL session و DP keys در طراحی پوشش دارند؛ آزمون اجرایی هنوز وجود ندارد |
| .gitignore | ۱۳ مسیر نمونهٔ build/IDE/secret/media/key/log/temp/database درست ignore شدند؛ شش مسیر نمونهٔ source/doc/config عمومی اشتباهاً ignore نشدند |
| اسکن راز | در متن اسناد/JSON/SQL و محتوای متنی ZIP الگوهای رایج private key، provider token و credential واقعی پیدا نشد؛ این کنترل جای secret scanner کامل نیست |
| مرجع‌های تحویل‌شده | hash هر ۴۵ فایل محلی ثابت است و با متناظر Frontend برابر است؛ ZIP بدون استخراج بررسی شد و نام فایل محرمانه در آن دیده نشد |
| Frontend | status ازپیش‌موجود تغییر نکرده؛ hash ۱۸ منبع مستقیم و اثر انگشت ۱۶۵۶ فایل tracked/untracked غیرignored در دو برداشت برابرند |
| Git | مخزن جدا در Backend با branch `main`؛ ثبت محلی فقط شامل اسناد تازه و مرجع‌های تحویل‌شده است؛ remote تعریف نشده و push انجام نشده؛ SHA از `git log -1` خوانده شود |

اثر انگشت تجمیعی Frontend در هر دو برداشت:

```text
files = 1656
SHA256 = 4c62ada397f13ecb0feb69b1f062bcd7f629b37be8a048fc8f6947abca2633d5
```

این اثر انگشت مسیر و بایت فایل‌های tracked/untracked غیرignored را پوشش می‌دهد؛ فایل ignored مانند env خوانده یا وارد مخزن نشده است. ابزارهای Frontend اجرا نشده‌اند. منابع، snapshot worktree فعلی‌اند و صرفاً به HEAD تاریخی نسبت داده نمی‌شوند.

## محدودیت منابع قدیمی

از ۱۰۳ پیوند محلیِ استخراج‌شده در بستهٔ مرجع، ۲۴ پیوند مقصد موجود ندارند؛ برای مثال `02-api/API-CONTRACTS.md` و `03-database/DATABASE-TABLE-BLUEPRINTS.md` در essential به layout نسخهٔ اصلی اشاره می‌کنند. این نقص از قبل در نسخهٔ تحویل‌شده است. برای حفظ hash منابع، فایل‌های قدیمی تغییر داده نشدند؛ فصل‌های متناظر موجود از مسیرهای صحیح در اسناد تازه لینک شده‌اند. جزئیات منشأ و نام سند مفقود در [شناسنامهٔ منابع](SOURCE_REFERENCES_FA.md) آمده است.

سند با نام دقیق `MASTER_PRODUCT_BUSINESS_SPECIFICATION_FA.md` یافت نشد. این کمبود و نبود mapping/SMS/IIS Production مانع تکمیل برنامه‌ریزی نیستند؛ برای پیاده‌سازی واقعی در checkpoint مربوط حل می‌شوند.

## حد اعتبار و توقف

هیچ کد Backend یا جدول تازه‌ای ساخته نشده، نرم‌افزاری نصب نشده و Frontend/سامانهٔ کارگزاری تغییر نکرده است. سازگاری package صرفاً از target metadata و مستندات رسمی بررسی شده و restore/build/security acceptance هنوز انجام نشده‌اند. در اجرای عادی shell یک خطای داخلی محیط رخ داد؛ کنترل‌ها با اجرای مورد تأیید ابزار و بدون تغییر دامنهٔ دسترسی پروژه تکمیل شدند.

**Phase 0 کامل و آمادهٔ بازبینی کاربر است. پیاده‌سازی Backend شروع نشده است.** گام مجاز بعدی فقط پس از اجازهٔ صریح کاربر، Checkpoint 1 در [PLAN.md](../PLAN.md) خواهد بود.
