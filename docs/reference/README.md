# بسته فارسی تحویل به تیم Backend

تاریخ: 2026-10-27. وضعیت: **مشخصات پیشنهادی برای بازبینی و تصویب؛ Backend تولیدی هنوز پیاده نشده است.** مبنای بررسی Frontend، شاخه `feat/unified-ui-admin-3d` در پروژه مرجع و نسخه `fbc1bba` به همراه جابه‌جایی مستندات `0e75f9c` است. این بسته بدون نیاز به تاریخچه گفت‌وگو قابل استفاده است.

## از کجا شروع کنیم؟

۱. ابتدا فصل‌های ۱ تا ۳، سپس ۱۰، ۱۵ و ۲۳ را بخوانید تا مالکیت هویت، الزامات قطعی و تصمیم‌های باز روشن شوند.
۲. فصل ۴ تمام **۶۳ عملیات منطقی** را با ورودی/خروجی، اختیار، اثر ذخیره‌سازی، خطا، retry، وابستگی و مرز کد فعلی پوشش می‌دهد. فصل ۵ آن‌ها را به **۵۵ ترکیب پیشنهادی method/path** نگاشت می‌کند؛ این شمار شامل alias‌های سازگاری و روش شرطی تبادل بلیت کارکنان است و تأیید نهایی endpoint‌ها نیست. فایل موجود `/site-bootstrap.json` و سه وظیفه رویداد/کارگر سرور جدا هستند.
۳. فصل‌های ۶ تا ۹ و ۲۰، **۳۷ جدول پیشنهادی، ۳۰۲ ستون، قیود و ۵۵ رابطه FK** را به قراردادها وصل می‌کنند. SQL فقط metadata می‌گیرد؛ رسانه در filesystem خصوصی است.
۴. فصل‌های ۱۱ تا ۱۴ چرخه عمر، تصمیم کارشناس، تنظیمات و تحویل نهایی را مشخص می‌کنند. فصل‌های ۱۶ تا ۲۲ و ۲۴ تا ۳۰ برای توافق میزبانی، برنامه اجرا و آزمون اتصال‌اند.

هیچ مسیر API، طرح SQL، TTL، سقف فایل، SLA یا روش SSO در این بسته قرارداد تأییدشده تلقی نمی‌شود مگر صریحاً به قاعده موجود محصول اشاره شده باشد. شماره/کد پیگیری به تنهایی احراز هویت نیست. فایل SQL روی هیچ پایگاهی اجرا نشده است. ساخت معمول Next با Static Export یکسان نیست؛ تحویل static کامل همچنان **مسدود** است.

## قواعد قطعی محصول

- بازدید تازه: **۱۰ عکس ثابت + دقیقاً یک عکس از چهار محل VIN =۱۱ عکس**، یک کیلومتر عددی جدا و یک ویدیوی الزامی پیاده‌روی دور خودرو. در قالب فعلی ۱۲ فایل رسانه وجود دارد؛ این مقدار از قالب مشتق است، نه ثابت سراسری. کیلومتر فایل نیست و ویدیو عکس نیست.
- هفت بخش، تجربه پیش‌فرض ۲D، انتخاب‌های `pillar/engine/seat/windshield` برای همان `spec-plate`، الزامی‌بودن مستقل `engine-bay` و سازگاری نسخه تاریخی ۱۲ عکسی حفظ می‌شوند.
- اصل پذیرفته‌شده، نسخه‌های قبلی، snapshot ارسال و دلیل اصلاح حذف یا بازبرچسب‌گذاری نمی‌شوند. گزینه راهنمای انتخاب‌شده، هویت عکس پذیرفته‌شده را عوض نمی‌کند.
- پایگاه و فایل خصوصی هر کارگزاری مستقل‌اند؛ Neshan زیرساخت مرکزی با کلید خصوصی خارج از مرورگر است. نشان و تنظیمات عمومی کارگزاری با هویت برنامه فرق دارند.
- تأیید Reviewer مساوی تحویل به سامانه بیمه نیست. فقط پس از رسید معتبر مقصد می‌توان `FORWARDED` نمایش داد.

## مدارک و حدود ادعا

کد جاری Frontend و کاتالوگ اصلی عملیات بررسی شده‌اند؛ بیشتر مرزهای تجاری هنوز mock/IndexedDB هستند. نقشه زنده در توسعه و بارگذار تنظیمات عمومی مرزهای واقعی موجودند، اما API تجاری ASP.NET، SSO تولیدی، SQL واقعی، انتقال نهایی و تضمین امنیت چندکاربره از این مخزن اثبات نمی‌شوند. راهنمای توسعه‌دهنده در [فهرست عمومی](../README.md) است؛ نیازهای ضروری Backend در همین بسته تکرار و روشن شده‌اند. برای تصمیم‌گیری، پاسخ‌ها و تصویب‌کننده هر مورد فصل ۲۳ را ثبت کنید؛ سپس OpenAPI نسخه‌دار تیم Backend مرجع تولید کلاینت خواهد بود.
