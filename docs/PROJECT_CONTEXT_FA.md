# زمینه و حدود پروژه

تاریخ تحلیل پایه: `2026-11-01`، منطقهٔ زمانی `Asia/Tehran`. بخش‌های مربوط به محدودهٔ Phase 0 در این سند تاریخی‌اند. **اکنون Checkpoint 1 با اجازهٔ صریح کاربر پیاده و محلی آزموده شده است**؛ [گزارش فعلی](CHECKPOINT1_IMPLEMENTATION_FA.md) مرجع وضعیت اجراست. قواعد محصول قطعی و schema/قابلیت‌های تجاری آینده همچنان طرح‌اند.

## هدف محصول

مشتری درخواست بیمه، پس از احراز شمارهٔ معتبر همان درخواست، اطلاعات خودرو و موقعیت را تأیید و مدارک را ثبت می‌کند؛ Backend مالک احراز هویت، مجوز، دادهٔ پایدار، دریافت امن فایل، ارسال و رسید است. Frontend فارسی/RTL موجود، بسیاری از رفتارها را با mock و IndexedDB شبیه‌سازی می‌کند؛ این رفتارها وجود سرویس Production را اثبات نمی‌کنند.

Backend جدید در `C:\Projects\vehicle-inspection-backend`، کاملاً جدا از Frontend در `C:\Projects\vehicle-inspection-integrated` است. از Backend اصلی کارگزاری سورس نداریم؛ اجازهٔ افزودن IIS Application داریم. استفاده از پایگاه موجود، اجازهٔ تغییر جدول‌های آن نیست.

## محدودهٔ تحویل

این مرحله فقط دستورهای پروژه، معماری، برنامه، تحلیل داده/قرارداد و معیار پذیرش می‌سازد. کد C#، solution، `global.json` اجرایی، تنظیمات استقرار، migration، اتصال SQL، SMS یا تغییر IIS ساخته/اجرا نمی‌شود. منابع تحویل‌شده حفظ می‌شوند و SQL مرجع اجرا نمی‌شود.

Phase 1 شامل Checkpointهای 1 تا 7 برای مشتری و بخش مشتری Checkpoint 9 است. Checkpoint 8 فاز بعدی کارکنان/کارشناس/تحویل کارگزاری است و مانع شروع یکپارچه‌سازی مشتری نیست. بدون آن، سامانه نباید تأیید کارشناسی یا تحویل نهایی را جعل کند.

## نتیجهٔ مطالعهٔ Frontend

فرم خودرو اکنون تأیید پلاک، رنگ و گزارش مغایرت دارد؛ make/model/year و VIN پوشانده در مدل هستند، ولی برای همهٔ مقادیر مفقود فرم ورود ندارد. فرم موقعیت مختصات، آدرس، دقت nullable و جزئیات اختیاری را می‌گیرد. رضایت نسخه‌دار پیش از تکمیل، و upload/summary/submit/status پس از capture لازم‌اند. تغییر آداپتور و فرم‌ها باید در کار مستقل Frontend و پس از قرارداد مصوب انجام شود؛ این مرحله Frontend را تغییر نمی‌دهد.

طرح قبلی ورود با ticket، SQL Server 2022، ۳۷ جدول بدون پیشوند و مسیر `/api` پیشنهادی است. دستور جاری، ورود referral/OTP، نسخهٔ نامعلوم SQL و پیشوندهای قطعی را جایگزین کرده است. [جزئیات تعارض‌ها و منشأ](SOURCE_REFERENCES_FA.md).

## محدودیت‌های واقعی

schema کارگزاری، قرارداد SMS و میزبان مقصد در دسترس نیستند؛ طراحی adapter و fixture مستقل از آن‌ها پیش می‌رود. سند با نام دقیق `MASTER_PRODUCT_BUSINESS_SPECIFICATION_FA.md` پیدا نشد؛ منابع کسب‌وکار موجود جایگزین مطالعه شده‌اند و معادل‌بودن کامل ادعا نمی‌شود. اسناد مرجع API در `docs/reference/` به‌صورت مسطح موجودند؛ نبود پوشهٔ محلی `API_FA/` به معنی نبود محتوای آن نیست.
